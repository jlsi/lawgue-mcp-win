配布・導入手順

検索・取得・保存は LAWGUE の Remote コネクタ、docx の解析・編集は Local MCP lawgue-jadeが担当します。プラグイン名は lawgue-mcp です。

Remote：LAWGUE コネクタ

LAWGUE への検索・取得・保存。利用者本人の権限でアクセスします。

＋
Local：lawgue-jade

docx の解析・編集。対応 OS の端末で実行します。

導入前に確認すること

Windows x64 版は Microsoft Visual C++ v14 ランタイムが必要です。VCRUNTIME140.dll が見つからない場合は、管理者の方針に従って Microsoft 公式の Visual C++ Redistributable（x64） をインストールしてください。runtime DLL や再頒布パッケージは同梱していません。

LAWGUE アカウント、対象文書への権限、ローカル編集機能の利用権、対応 OS が必要です。Claude 側のプラン・組織ポリシーでもコネクタとプラグインの利用が許可されていることを確認します。

ローカル編集でも、ツールが返す本文やコメントは AI サービスへ渡ります。組織の情報管理方針と各サービスのデータ取扱条件に従ってください。

利用する画面と配布物

このリポジトリは端末上の Claude Code 用です。Desktop のチャットには、別途対応 OS の .mcpb が必要です。本リポジトリに .mcpb はありません。Cowork はプラグイン内 Local MCP に対応していますが、本バイナリの Cowork 実行環境での動作は未確認です。Web・モバイルのチャットでは、この端末用バイナリを実行できません。

接続方式の公式説明を参照してください。

Remote コネクタを登録する

01

URL と OAuth Client ID を指定

個人利用は Customize → Connectors、組織利用は登録権限を持つ管理者が Organization settings → Connectors からカスタムコネクタを追加します。

  • URL：https://api.lawgue.com/mcp
  • OAuth Client ID：579ca0est193bdhvh0b9qp1uvt
  • OAuth Client Secret：空欄

認証を伴う接続を選び、Use your own OAuth client を選択して上記 ID を入力します。旧画面の Advanced settings でも同じ値を使います。URL と ID は同じ環境の組み合わせを使ってください。Client ID は公開クライアントの識別子で、Client Secret の受領・入力は不要です。

URL だけで登録して認証に失敗する場合は、削除して登録し直します。

02

操作権限を設定し、各利用者が接続

各利用者が自分の LAWGUE アカウントで接続します。Tool permissions は組織方針に従い、更新・保存を利用者が承認できる設定にします。不要な操作は許可しません。この設定で LAWGUE 側のアクセス権が広がることはありません。

組織配布の注意点

方式A：Claude Code の CLI から導入

A1

Marketplace を追加してインストール

claude plugin marketplace add jlsi/lawgue-mcp-win
claude plugin install lawgue-mcp@lawgue-mcp-win --scope user

public 化が完了するまでは GitHub の閲覧権限が必要です。公開後の取得に、このリポジトリへの招待は不要です。反映の案内に従って /reload-plugins または再起動を行います。

A2

Remote と Local を確認

/mcp で Local の lawgue-jade と Remote の LAWGUE ツールを確認します。Remote が表示されない場合は、以下で直接登録できます。既に表示されるコネクタと重複登録しないでください。

claude mcp add --scope user --transport http --client-id 579ca0est193bdhvh0b9qp1uvt --callback-port 40342 lawgue https://api.lawgue.com/mcp
claude mcp login lawgue

40342 番ポートが利用可能であることを確認します。

A3

更新方法

自動更新は /plugin → Marketplaces → lawgue-mcp-win から設定します。手動更新は次の順に実行します。

claude plugin marketplace update lawgue-mcp-win
claude plugin update lawgue-mcp@lawgue-mcp-win

反映の案内に従って /reload-plugins または再起動を行います。

方式B：Desktop Extension（別配布）

対応 OS の .mcpb が提供されている場合

Claude Desktop の Settings → Extensions → Advanced settings → Install Extension… から、提供元と対象 OS を確認したファイルを選択します。GitHub リポジトリの ZIP は、拡張子を変更しても .mcpb になりません。導入後は Extension の詳細でツールを確認します。

更新は提供元の案内に従います。GitHub Marketplace の更新とは別です。

方式C：組織への配布

管理者が配布方式を確認

Claude Code の管理設定と、Claude の組織向け Plugins & skills は別の仕組みです。公開 GitHub リポジトリは、組織 Marketplace の GitHub 同期元として直接登録できません。管理者は 組織向けプラグインの公式手順に従い、対応 OS と権利表示を保った配布物で検証してください。

Desktop のチャットへの組織配布には別途 .mcpb が必要です。Desktop Extension の公式手順と組織ポリシーを確認します。

動作確認

検証用文書で試す

  1. 組織で用意した検証用文書を、文書名・プロジェクトを指定して検索します。
  2. 対象文書を確認してから開き、小さな変更を依頼します。
  3. 保存前の変更点を確認して保存を承認し、LAWGUE 側でも保存結果を確認します。

法令辞書や AI の出力はレビューの補助です。必要な確認を人が行ってください。

トラブルシューティング

認証に失敗するURL と Client ID の環境、Client Secret が空欄かを確認します。設定を誤ったコネクタは削除して登録し直します。
Remote ツールが重複する旧プラグイン内の Remote、カスタムコネクタ、CLI 直接接続の重複を確認し、必要な接続を1つ選びます。
Local が表示されない対応 OS、プラグイン名 lawgue-mcp、有効状態、組織ポリシーを確認します。Desktop チャットには .mcpb が必要です。
Cowork で起動できない本バイナリの Cowork での動作は未確認です。対応 OS の端末上で Claude Code を使用します。
実行がブロックされる提供元と配布物を確認し、OS の正規の許可手順と会社のセキュリティ方針に従います。解決できない場合は管理者・提供元へ問い合わせます。
利用権のエラーが出るLAWGUE への接続と利用権を確認します。再接続で解決しない場合は契約窓口へ問い合わせます。
